# Feature Specification: 세션 연결 그래프 (Session Graph)

**Feature Branch**: `feat/session-graph`
**Created**: 2026-10-15
**Status**: Draft
**Input**: User description: "테스크(칸반) 형식이 아니라 연결 차트 형식으로 한눈에 보이게." 참고: 왼쪽 프로젝트 → 가운데 작업 줄기 → 오른쪽 에이전트 카드(이름·KAN·도구·브랜치·역할 배지·상태 점), 카드끼리 화살표로 의존 관계.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프로젝트별 에이전트를 연결 차트로 본다 (Priority: P1)

통합 보드를 열면 기본 화면이 연결 차트다. 왼쪽 열에 프로젝트, 오른쪽 열에 그 프로젝트에서 도는 에이전트 세션 카드가 선으로 이어져 있다. 카드에는 폴더(워크트리) 이름, 도구(claude/codex), git 브랜치, 상태 점(작업 중/나를 기다림/완료/상태 모름), 최근 프롬프트가 보인다. 같은 저장소의 워크트리 세션은 원래 프로젝트 아래에 묶인다.

**Why this priority**: 사용자가 원하는 "한눈에" 화면의 본체.

**Independent Test**: 서로 다른 프로젝트와 같은 프로젝트의 워크트리에서 세션 이벤트를 보내면, 차트에 프로젝트 노드 2개와 각 세션 카드가 선으로 연결되어 보이고 워크트리 카드는 원래 프로젝트에 묶인다.

**Acceptance Scenarios**:

1. **Given** db-ga-dashboard와 그 워크트리 db-ga-dashboard-perf에서 세션이 돈다, **When** 차트를 연다, **Then** db-ga-dashboard 노드 하나에 두 카드가 연결되고 각 카드에 자기 브랜치가 표시된다.
2. **Given** 세션이 "나를 기다림"으로 바뀐다, **When** 차트를 보고 있다, **Then** 5초 안에 그 카드가 강조되고 상태 점 색이 바뀐다.
3. **Given** 상태 모름 프로세스 3개가 있는 폴더, **When** 차트를 본다, **Then** 그 프로젝트에 "상태 모름 3" 카드 하나가 연결된다.
4. **Given** 차트 화면, **When** 상단 전환에서 "칸반"을 고른다, **Then** 기존 티켓 칸반이 보이고, 선택은 다음 방문에도 유지된다.

---

### User Story 2 - 역할과 작업 줄기로 정리한다 (Priority: P1)

카드의 역할 배지(main/plan/implement/review/experiment)를 골라 바꿀 수 있고, 카드에 작업 줄기 이름(예: "rate limiting")을 붙이면 같은 이름의 카드들이 프로젝트와 카드 사이 가운데 노드로 묶인다.

**Why this priority**: 여러 에이전트를 "누가 무엇을 하는지"로 정리하는 핵심 조작.

**Independent Test**: 카드 두 개에 같은 작업 줄기 이름을 붙이면 가운데 노드 하나로 묶이고, 역할을 review로 바꾸면 배지가 바뀌며 새로고침 후에도 유지된다.

**Acceptance Scenarios**:

1. **Given** 카드 하나, **When** 역할 배지에서 review를 고른다, **Then** 배지가 review로 바뀌고 새로고침 후에도 유지된다.
2. **Given** 같은 프로젝트 카드 2개, **When** 둘 다 작업 줄기 "minor units"를 지정한다, **Then** 프로젝트 → "minor units" → 두 카드로 선이 이어진다.
3. **Given** 작업 줄기가 없는 카드, **When** 차트를 본다, **Then** 프로젝트에서 카드로 바로 선이 이어진다.

---

### User Story 3 - 에이전트 사이 의존 관계를 화살표로 잇는다 (Priority: P2)

카드 오른쪽 점을 다른 카드로 끌어 놓으면 "이 작업이 끝나야 저 작업"이라는 화살표가 생기고, 화살표를 누르면 지워진다.

**Why this priority**: 구현 → 리뷰처럼 넘겨받는 흐름을 보여주는 보조 기능.

**Independent Test**: 카드 A의 점을 카드 B로 끌면 A→B 화살표가 생기고, 새로고침 후에도 남으며, 화살표 클릭 시 사라진다.

**Acceptance Scenarios**:

1. **Given** 카드 A, B, **When** A의 점을 B에 놓는다, **Then** A에서 B로 곡선 화살표가 그려진다.
2. **Given** A→B 화살표, **When** 화살표를 클릭한다, **Then** 화살표가 지워진다.
3. **Given** A→B, **When** B에서 A로 다시 연결을 시도한다, **Then** 순환은 만들지 않고 안내한다.

---

### Edge Cases

- 세션이 끝나 카드가 사라지면 그 카드의 역할·작업 줄기·화살표도 함께 정리한다.
- 브랜치를 읽을 수 없는 폴더(git 아님)는 브랜치 없이 표시한다.
- 세션이 많아(20개 이상) 화면을 넘으면 세로로 스크롤된다. 좁은 화면(폰 폭)에서는 프로젝트별 세로 목록으로 접힌다.
- 작업 줄기 이름은 최대 40자.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 통합 화면은 "차트"와 "칸반" 두 보기를 전환할 수 있어야 하며 기본은 차트다.
- **FR-002**: 차트는 프로젝트(왼쪽) → 작업 줄기(가운데, 있을 때만) → 세션 카드(오른쪽)를 선으로 잇는다.
- **FR-003**: 세션은 git 공통 저장소 기준으로 프로젝트에 묶인다(워크트리는 원래 저장소 아래). git이 아니면 폴더 기준.
- **FR-004**: 카드 제목은 Claude Code가 붙인 세션 제목(터미널 탭 이름과 동일, 세션 기록의 `ai-title`)이고, 없으면 폴더 이름이다. 카드는 제목과 함께 폴더 이름, 도구, 브랜치, 상태 점, 최근 프롬프트 또는 대기 메시지, 경과 시간을 보여준다.
- **FR-005**: 사용자는 카드 역할(main/plan/implement/review/experiment)과 작업 줄기 이름을 지정할 수 있고, 값은 서버 재시작 후에도 유지된다(세션이 살아 있는 동안).
- **FR-006**: 사용자는 카드 사이 의존 화살표를 끌어서 만들고 클릭해서 지울 수 있다. 순환은 거부한다.
- **FR-007**: 상태 모름 프로세스는 그 폴더의 최근 Claude Code 세션 기록에서 제목을 찾아 이름 있는 카드로 보여주고, 찾지 못한 나머지는 프로젝트별 묶음 카드 하나로 보여준다. Codex는 "Codex · 폴더"로 표시한다.
- **FR-008**: 상태 변화는 5초 안에 차트에 반영되고, 화면 갱신이 사용자의 드래그·선택 중 조작을 끊지 않는다.

### Key Entities

- **세션 카드**: 기존 세션 + 브랜치, 역할, 작업 줄기.
- **의존 화살표**: 시작 세션 ID → 끝 세션 ID.
- **그래프 주석(저장)**: 세션 ID별 역할·작업 줄기, 화살표 목록.

## Success Criteria *(mandatory)*

- **SC-001**: 차트 하나로 모든 프로젝트의 에이전트 수·상태를 화면 이동 없이 파악한다.
- **SC-002**: 상태 변화가 5초 안에 반영된다.
- **SC-003**: 역할·작업 줄기·화살표 변경이 새로고침과 서버 재시작 뒤에도 유지된다.

## Assumptions

- 대상은 spec 002의 세션(직접 띄운 Claude Code·Codex). Symphony 티켓은 칸반 보기에 그대로 둔다.
- 역할은 사용자가 붙이는 표시이며 에이전트 동작을 바꾸지 않는다.
- 주석은 `~/.symphony/unified-graph.json`에 저장한다(세션 ID, 역할, 작업 줄기, 화살표만; 프롬프트 저장 안 함).
- 그래프 라이브러리 없이 HTML 카드 + SVG 곡선으로 그린다.
