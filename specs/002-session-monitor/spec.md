# Feature Specification: 세션 감시 (Session Monitor)

**Feature Branch**: `feat/session-monitor`
**Created**: 2026-10-15
**Status**: Draft
**Input**: User description: "통합 보드에서 뭐가 도는지 안 보인다. 내가 직접 띄운 Claude Code 터미널들이 어느 프로젝트에서 작업 중인지, 나를 기다리는지, 끝났는지 한 화면에서 보고 싶다." (릴스: AI 터미널 여러 개 → 프로젝트별 카드, 작업 중/리뷰 대기/알림)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 내 Claude Code 세션이 지금 뭘 하는지 본다 (Priority: P1)

사용자가 여러 터미널에서 Claude Code를 띄워 두고 통합 보드를 열면, 프로젝트(폴더)별로 세션이 보이고 각 세션이 **작업 중 / 나를 기다림 / 완료** 중 어떤 상태인지 바로 안다.

**Why this priority**: 사용자의 직접 불만("왜 뭐가 도는지 안 보여")을 해결하는 핵심.

**Independent Test**: 한 프로젝트 폴더에서 Claude Code에 프롬프트를 보내면 보드의 해당 프로젝트에 "작업 중" 세션이 나타나고, 응답이 끝나면 "완료"로 바뀐다.

**Acceptance Scenarios**:

1. **Given** 통합 보드가 열려 있음, **When** db-ga-dashboard 폴더의 Claude Code에 프롬프트를 보낸다, **Then** 5초 안에 db-ga-dashboard 아래 "작업 중" 세션이 보이고 보낸 프롬프트 앞부분이 표시된다.
2. **Given** 세션이 작업 중, **When** Claude가 응답을 마친다, **Then** 상태가 "완료"로 바뀌고 마친 시각이 표시된다.
3. **Given** 같은 폴더에서 세션 3개가 돌고 있음, **When** 보드를 본다, **Then** 세 세션이 따로 보인다.
4. **Given** 등록되지 않은 폴더(예: db-insurance)에서 세션이 돈다, **When** 보드를 본다, **Then** "등록 안 된 폴더" 묶음 아래 폴더 이름과 함께 보인다.

---

### User Story 2 - 나를 기다리는 세션을 놓치지 않는다 (Priority: P1)

Claude Code가 권한 요청이나 질문으로 멈추면, 보드에서 그 세션이 눈에 띄게 강조되고 브라우저 알림과 탭 제목 숫자로 알려준다.

**Why this priority**: 여러 터미널을 띄우면 "어디서 나를 기다리는지" 모르는 게 가장 큰 손실이다.

**Independent Test**: 권한이 필요한 도구 실행을 유도해 세션이 멈추면 보드에 "나를 기다림"이 강조되고 알림이 뜬다.

**Acceptance Scenarios**:

1. **Given** 세션이 작업 중, **When** Claude Code가 권한 확인이나 입력 대기 알림을 보낸다, **Then** 그 세션이 "나를 기다림"으로 바뀌고 알림 메시지가 표시된다.
2. **Given** 브라우저 알림을 허용함, **When** 어떤 세션이 "나를 기다림"으로 바뀐다, **Then** 데스크톱 알림이 한 번 뜬다(같은 대기에 반복 알림 없음).
3. **Given** 기다리는 세션이 2개, **When** 탭 제목을 본다, **Then** 대기 수가 표시된다.
4. **Given** 기다리던 세션에 사용자가 답한다, **When** 작업이 재개된다, **Then** 다시 "작업 중"으로 바뀐다.

---

### User Story 3 - 감시를 켜기 전부터 떠 있던 세션도 보인다 (Priority: P2)

훅 설치 전부터 떠 있던 세션이나 상태 이벤트를 아직 안 보낸 세션도, 실행 중인 Claude Code·Codex 프로세스를 찾아 "실행 중(상태 모름)"으로 보여준다.

**Why this priority**: 설치 직후에도 빈 화면이 아니어야 한다. 정확한 상태는 이벤트가 오면 채워진다.

**Independent Test**: 이벤트를 보낸 적 없는 Claude Code 프로세스가 떠 있는 폴더가 보드에 "실행 중(상태 모름)"으로 보인다.

**Acceptance Scenarios**:

1. **Given** 이벤트를 보낸 적 없는 claude 프로세스 2개가 node-manager에서 실행 중, **When** 보드를 연다, **Then** node-manager 아래 상태 모름 세션 수가 보인다.
2. **Given** 프로세스가 종료됨, **When** 다음 감지 주기가 돈다, **Then** 해당 항목이 사라진다.

---

### Edge Cases

- 통합 서버가 꺼져 있을 때: 훅은 실패해도 Claude Code 동작을 막거나 늦추지 않는다(1초 안에 포기, 오류 무시).
- 세션이 이벤트 없이 사라짐(터미널 강제 종료): 세션 종료 이벤트가 없어도 일정 시간(완료 후 30분, 상태 모름은 프로세스 소멸 시) 뒤 목록에서 정리한다.
- 하위 폴더에서 실행(예: `db-ga-dashboard/src`): 상위 등록 프로젝트에 묶인다.
- 서브에이전트 이벤트: 메인 세션 상태를 덮어쓰지 않는다.
- 통합 서버 재시작: 세션 목록은 비었다가 다음 이벤트·프로세스 감지로 다시 채워진다(영구 저장 안 함).
- 프롬프트 내용에 민감 정보가 있을 수 있음: 앞부분 일부(최대 120자)만 메모리에 두고 디스크에 저장하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 Claude Code 세션의 상태 이벤트(세션 시작, 프롬프트 제출, 응답 완료, 알림/권한 대기, 세션 종료)를 로컬에서 받아야 한다.
- **FR-002**: 각 세션은 세션 ID, 작업 폴더, 소속 프로젝트(등록 프로젝트 경로 하위면 그 프로젝트, 아니면 폴더 이름), 상태(작업 중/나를 기다림/완료/상태 모름), 마지막 이벤트 시각, 최근 프롬프트 앞부분, 대기 메시지를 가진다.
- **FR-003**: 통합 화면은 프로젝트별로 세션을 묶어 보여주고, 상태 변화를 5초 안에 반영해야 한다.
- **FR-004**: "나를 기다림" 세션은 강조 표시, 탭 제목 숫자, 브라우저 알림(사용자가 허용한 경우, 대기 1회당 1번)으로 알려야 한다.
- **FR-005**: 시스템은 주기적으로(최대 15초) 실행 중인 Claude Code·Codex 프로세스와 작업 폴더를 감지해, 이벤트가 없는 세션을 "상태 모름"으로 보여줘야 한다.
- **FR-006**: 이벤트 전송 훅은 서버가 없거나 느려도 Claude Code를 1초 이상 지연시키거나 실패시키지 않아야 한다.
- **FR-007**: 훅 설치는 기존 사용자 훅을 지우거나 바꾸지 않고 추가만 해야 하며, 제거 명령으로 깨끗이 되돌릴 수 있어야 한다.
- **FR-008**: 세션 정보는 메모리에만 두고 디스크에 저장하지 않는다. 프롬프트는 앞 120자까지만 보관한다.
- **FR-009**: 종료 이벤트가 없더라도 완료 후 30분 지난 세션, 프로세스가 사라진 상태 모름 항목은 자동 정리한다.
- **FR-010**: 이벤트 수신 엔드포인트는 기존과 같은 로컬 보호(루프백, 호스트 검사, 교차 출처 차단)를 따른다.

### Key Entities

- **세션(AgentSession)**: 세션 ID, 도구(claude/codex), 작업 폴더, 프로젝트 ID 또는 폴더 이름, 상태, 최근 프롬프트(120자), 대기 메시지, 시작·마지막 이벤트 시각.
- **세션 이벤트(SessionEvent)**: Claude Code 훅이 보내는 이벤트 이름, 세션 ID, 작업 폴더, 부가 정보(프롬프트·알림 메시지).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 터미널에서 프롬프트를 보내면 5초 안에 보드에 "작업 중"으로 보인다.
- **SC-002**: 권한·입력 대기가 생기면 5초 안에 강조·알림이 뜬다.
- **SC-003**: 통합 서버가 꺼진 상태에서 Claude Code 프롬프트 응답 시간이 훅 때문에 1초 넘게 늘지 않는다.
- **SC-004**: 설치 직후 이미 떠 있던 세션 수가 보드의 "상태 모름" 수와 일치한다.

## Assumptions

- 상태 이벤트는 Claude Code 훅(SessionStart, UserPromptSubmit, Stop, Notification, SessionEnd)으로 받는다. Codex는 이번 범위에서 프로세스 감지(상태 모름)만 지원한다.
- 훅은 전역 `~/.claude/settings.json`에 추가한다(모든 Claude Code 세션 대상). 사용자가 이 변경을 승인했다.
- 단일 사용자 로컬 환경. 통합 서버는 launchd로 상시 실행 중이다(spec 001).
- Symphony가 직접 돌리는 티켓 워커(`claude -p`)는 기존 칸반 카드에 이미 보이므로 세션 목록에서 제외한다.
